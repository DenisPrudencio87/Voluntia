# Arquitectura técnica
Monolito modular con frontend Angular standalone + TypeScript + Bootstrap 5 + Bootstrap Icons + Reactive Forms; backend FastAPI/Python, Pydantic, SQLAlchemy síncrono, psycopg, Alembic; PostgreSQL en Supabase y Storage; Git/GitHub Actions, Pytest, pruebas Angular y Playwright. Docker multietapa para servir Angular compilado y FastAPI desde una URL Render. Elegir versiones estables compatibles con herramientas instaladas, fijarlas en lockfile/requirements e indicar versiones exactas en README; no usar prereleases. No añadir frameworks redundantes. Signal Forms no es requisito explícito de esta rúbrica; Reactive Forms simplifica la explicación.

## Comunicación
Navegador → Angular → /api/v1 → routers FastAPI → servicios de negocio → SQLAlchemy/PostgreSQL. Swagger /docs, /api/health y /api/ready (DB sin exponer detalles). API externa de correo transaccional, preferentemente Resend si cuenta configurada; adaptador HTTP, timeout, manejo de fallos, modo fake únicamente pruebas/desarrollo. Supabase Storage desde backend con credencial servidor; nunca exponer service role ni DSN al frontend. Configuración de producción falla claramente si faltan secretos esenciales; no simular éxito de correo. Reenvío de verificación con límites.

## Estructura
frontend/src/app/{components,pages,services,models,guards}; backend/app/{routers,services,models,schemas,security}; backend/migrations; backend/tests; database/{schema.sql,functions.sql,triggers.sql,queries.sql}; docs; scripts; .github/workflows/ci.yml; Dockerfile; .env.example; .gitignore; README.md. Mantener rutas claras y lógica de negocio en servicios. API prefijo /api/v1; errores 400/401/403/404/409/422/429 según corresponda, sin stack traces. SPA fallback solo para rutas frontend, nunca interceptar /api ni /docs.

## Seguridad mínima
Argon2id; JWT corto en cookie HttpOnly, Secure en producción, SameSite=Lax; CSRF token y validación Origin para escrituras autenticadas, mismo origen en producción. No almacenar JWT en localStorage. Revalidar estado/roles/membresía en cada petición; invalidar sesiones tras cambio de contraseña mediante fecha_actualizacion o mecanismo documentado sin agregar tablas (usar timestamp de actualización de seguridad con semántica explícita). Rotar/revocar tokens de recuperación y no revelar existencia de cuenta. Rate limit login, registro, recuperación, verificación y postulación, con límites por cuenta/IP y respuesta 429; solución sencilla en proceso para un único worker, documentar limitación al escalar. Consultas parametrizadas, no interpolar SQL; XSS mediante escape Angular, CSP razonable, HTTPS, headers seguros. No registrar credenciales. Roles mínimos DB, esquema privado sin exposición directa a PostgREST, evitar claves privilegiadas para conexión habitual; credenciales de migración separadas. RLS o revocar acceso de anon/authenticated si aplica; acceso únicamente backend. CORS limitado al origen local necesario, sin wildcard con credenciales.

## Entornos
Local: PostgreSQL dedicado (Docker Compose opcional), almacenamiento local aislado y correo capturado; Angular dev proxy /api. CI: servicio PostgreSQL descartable y adaptadores fake; pruebas no usan producción. Producción: Supabase separado, Storage privado y Render; secretos por variables de entorno. Migraciones por comando explícito controlado antes de despliegue, sin reset ni seed demo automático. Demo pública separada de datos reales, cuentas limitadas, sin administrador público compartido. Crear administrador mediante comando seguro con secreto ingresado por el propietario. Backup/restauración documentados. Render puede tener arranque en frío según plan; probar antes de exposición. No contratar servicios ni publicar sin autorización explícita del propietario.
