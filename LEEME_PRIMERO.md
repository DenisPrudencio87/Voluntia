# Preparación de Voluntia para Codex
Este paquete contiene documentación, no la aplicación programada. Extrae el ZIP y abre la carpeta Voluntia en VS Code. Si ya tienes una carpeta, copia los archivos sin sobrescribir código existente. Conserva la rúbrica PDF original. Los documentos de referencia históricos no gobiernan la implementación.

1. En PowerShell dentro de Voluntia ejecuta `node -v`, `npm.cmd -v`, `python --version`, `git --version`, `docker --version`, `gh --version` (los dos últimos son opcionales al inicio; Docker o PostgreSQL local será necesario para pruebas). Si falta algo, Codex puede documentarlo y continuar con tareas no bloqueadas.
2. Si no existe repositorio: `git init -b main`. Abre `code .`. Inicia sesión en extensión Codex. Trabaja en una carpeta independiente, no en el repositorio del hospital.
3. Selecciona modo agente con permisos de escritura en workspace. Si tu versión ofrece revisión automática/Auto-review, úsala para minimizar solicitudes. Los nombres y disponibilidad dependen de versión. No necesitas Full Access; si decides usar permisos amplios, utiliza una VM aislada sin secretos ni datos reales. La política de permisos de la herramienta prevalece sobre el prompt.
4. En el chat de Codex pega: `Lee AGENTS.md y PROMPT_MAESTRO.md y ejecuta el encargo completo. No te limites a planificar. Continúa con las fases independientes si hay bloqueos externos.`
5. Para reanudar: `Lee docs/PROGRESO.md, verifica git status y continúa desde la primera fase pendiente siguiendo AGENTS.md.`
6. Crea cuentas/proyectos GitHub, Supabase, Render y proveedor correo cuando sean necesarios. Introduce secretos localmente en .env ignorado o panel del proveedor, jamás en chat/README/Git. Autoriza explícitamente el remoto y el despliegue cuando hayas revisado los resultados. No usar producción para pruebas. Codex puede necesitar intervención por permisos, login, cuotas o límite de contexto; no se garantiza una ejecución única desatendida.
7. Antes del examen comprueba URL desde otro equipo, CI, PR, funciones SQL y recorrido demo. Practica guía de sustentación. No entregar sin conocer código y poder explicarlo.

## Cambios respecto al original
Se mantienen 23 de 29 tablas; se posponen seis y el rol moderador. Se decide alcance, estados/transiciones, cancelación antes del inicio, aprobación documental, correo externo, acceso privado a archivos, estrategia de sesiones y despliegue unificado. Estas son decisiones de diseño propuestas, no requisitos textuales de la rúbrica. El paquete no crea cuentas, no modifica bases ni ejecuta pruebas de aplicación. La rúbrica exige dominio individual: verifica y aprende el código generado y respeta las reglas académicas de tu curso.
